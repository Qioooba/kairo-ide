## 0. TL;DR — 最严重的 5 个

1. **核心流程跑不通** — Go 端 `internal/tomcat6/tomcat6.go:486` 的 `Start()` 永远返回 `"legacy Start() not supported"`，生产里 POST `/api/v1/servers` 必然 500；前端 `KairoProduct`（服务层 ContainerModule）从未被 load，所有 widget 按钮一按就 NPE。**当前 binary 在产品上不能 build / 不能启 Tomcat**。
2. **事件总线单例 bug** — `packages/runtime-extension/src/browser/runtime-connection-service.ts:398-417` 的 `connectEvents` 用 `ws.onmessage = ...` 直接覆盖，3 个 store（build / server / log viewer）共用一个 `eventSocket`，**谁最后注册谁独占事件**。build 进度和 server 状态会静默丢失，无报错。
3. **Go 端整层 use case 是死代码** — `internal/app/` 整层（2,244 行 prod + 2,169 行 test）bootstrap 没 wire；`internal/proc` (1,629 行) 95% 路径不跑；ADR-0011 描述的进程身份校验、opLocks、portAllocator、shutdown flag——**全没生效**。
4. **文档与代码严重脱节** — `DELIVERY.md` 描述"实拍通过"；`MILESTONES.md` 承认"blocked / partial / not_started"；`apps/server/src/index.ts:228-231` 注释 `// (Real impl: serve the built bundle from apps/browser/lib.)` 但代码是 HTML 占位符。
5. **`patches/inversify@6.2.2.patch` 是选错版本的标志** — Theia 1.73 已迁去 `@inversifyjs/core`，项目仍用 2019 年的 `inversify@6.2.2` + 自定义 patch 绕过 `DUPLICATED_INJECTABLE_DECORATOR`。**真问题是被多个 module 重复 @injectable，patch 绕过报错但没修根因**。

### P0-4. 修 `internal/jdtls/distribution.go:786-797` defer Remove bug

**问题**：
```go
tmp, err := os.CreateTemp(dir, "jdtls-*.tmp")  // line 786
if err != nil { return err }
defer os.Remove(tmp.Name())  // line 787  <-- 关键 bug
// ... download + write to tmp
if err := os.Rename(tmp.Name(), dest); err != nil { return err }  // line 797
// 注意：defer Remove 在函数返回时执行，此时 tmp.Name() 路径已变成 dest
// os.Remove(tmp.Name()) 会删 dest 文件！
```

**修复**：
```go
tmp, err := os.CreateTemp(dir, "jdtls-*.tmp")
if err != nil { return err }
tmpName := tmp.Name()  // capture before any rename
// ... download + write
if err := os.Rename(tmpName, dest); err != nil {
    os.Remove(tmpName)  // 失败路径才删 tmp
    return err
}
return nil  // 成功路径不再删
// 或: tmp.Close() 后立刻 os.Remove(tmpName)（Unix 上 unlink 打开的文件是 OK 的）
```

**更稳的修法**：用 `*os.File.Name()` 在 Close 后立即 unlink tmp（Unix 上是允许的，文件 inode 仍存在直到 close），然后再 Rename——但 Go 的 `atomicfile.Rename` 已经处理，先确认 `internal/atomicfile/atomicfile.go:31-58` 的语义。

**验证**：
