## 3. 逐项门禁分析

### 3.1 冷启动 (`coldStart`) — ✅ 通过

- **建议**: 使用 `run-perf-baseline.cjs` 进行真实 cold-start 测量（需要 Playwright + 运行的 Theia）。

### 3.2 文件打开 P95 (`fileOpenP95`) — ✅ 通过
- **2026-07-23**: 0s (P95 = 0.0516s)
- **2026-07-24**: 0s (P95 = 0.2846ms)
- **分析**: 代理方式（fs.readFile 10KB），真实值远低于 0.3s 目标。

### 3.3 首次 Java Completion (`firstCompletion`) — ⏭️ 跳过
- **原因**: Go agent 未运行，无法测量真实 completion 延迟。
- **影响**: 这是核心 IDE 体验指标，必须在真实 IDE 运行环境中测量。
- **建议**: 启动 `pnpm agent:run` 后重新运行门禁。

### 3.4 后续 Completion P95 (`subsequentCompletionP95`) — ⏭️ 跳过
- **原因**: 同上，Go agent 未运行。
- **建议**: 与 firstCompletion 一起在 agent 运行后测量。

### 3.5 增量编译 (`incrementalBuild`) — ✅ 通过

- **分析**: 门禁脚本在 Windows 上回退到了 Go build（无 tsc），但都远低于 2s 目标。
- **注意**: 两个平台使用了不同的编译方法，不直接可比。

- **分析**: Windows 上 `find` 命令性能显著低于 macOS（10x 差距）。这是 Windows 文件系统的已知限制。
- **建议**: 考虑使用 `git ls-files` 或 ripgrep 替代 `find` 提升 Windows 搜索性能。

### 3.8 UI 输入响应 P95 (`uiInputResponseP95`) — ✅ 通过

### 3.9 空闲 CPU (`idleCPU`) — ❌ 未通过
- **2026-07-23**: 30.29% (macOS, 10 CPUs)
- **2026-07-24**: 10.63% (Windows, 40 CPUs)
- **目标**: < 3%
- **分析**: 这是一个**误报性门禁**。门禁脚本测量的是运行脚本期间的 CPU 使用率，而非真正的 IDE 空闲 CPU。脚本本身在 40 核机器上就有 10% 的 CPU 使用率。
- **建议**:
  1. 将此门禁改为仅对 **IDE 稳态运行** 时测量（需要 Playwright + 运行中的 IDE）
  2. 或者将目标从 3% 调整为 15%（在 40 核机器上 3% ≈ 1.2 核，过于严格）
  3. 在 `run-perf-gate.cjs` 中使用百分比而非绝对值

## 5. 门禁脚本分析

### `scripts/run-perf-gate.cjs`
- **功能**: 测量 10 项 Master Plan §9.2 指标
- **平台兼容性**: 
  - ✅ `isWindows()` 函数检测平台
  - ✅ 使用 `spawnSync` + `windowsHide: true`
  - ⚠️ 搜索指标使用 `sh -c` + `find`/`grep`（Windows 需 WSL/Git Bash）
  - ⚠️ `ps -o %cpu=` 在 Windows 上不可用（使用 `tasklist` 替代）
  - ⚠️ CPU 测量在 Windows 上使用 `os.cpus()` 但采样间隔长
- **建议改进**:
  1. 在 Windows 上使用 `Get-CimInstance` 或 `typeperf` 替代 `ps`
  2. 将 `find` 替换为 `Get-ChildItem -Recurse` 或 ripgrep
  3. 添加 `--skip-agent` 标志跳过 agent 依赖的测试

### `scripts/run-perf-baseline.cjs`
- **功能**: 通过 Playwright 进行真实浏览器内性能测量
- **限制**: 需要运行中的 Theia IDE (`:3000`) 和 Go agent (`:18080`)
- **Windows 兼容性**: Playwright Chromium 在 Windows 上完全支持

### `scripts/run-perf-benchmark.cjs`
- **功能**: 综合基准测试（Go 测试、前端测试、代码行数、包大小）
- **限制**: 使用 `sh -c` + `find`/`xargs`（Windows 需 WSL）
- **建议**: 添加 PowerShell 回退路径
