# Progress — v0.3-encoding

> Tag: `v0.3-encoding`
> Round: P3 (encoding rewrite) — first of one
> Date: 2026-07-18

## What is in this tag

The user called this out as a core feature, not an addon.
Your legacy project is GBK, so the IDE MUST round-trip
non-UTF-8 bytes faithfully. This tag delivers the honest
plumbing: status bar shows the active file's encoding, the
"Reopen with Encoding" and "Save with Encoding" commands
are real flows (not toasts), the encoding is registered
with Theia's `EncodingRegistry` so plain Ctrl+S also
respects it, and the canEncode guard refuses to save
bytes the chosen encoding cannot represent.

### Backend (Go)

- `internal/encoding/encoding.go`:
  - Fixed a real false-positive in `Detect`: the defaultEnc
    fall-back used to return `utf-8` even when the bytes
    were not valid UTF-8 (because `unicode.UTF8` decoder
    silently replaces invalid bytes with U+FFFD). The new
    `canDecodeAs` uses `utf8.Valid` for the UTF-8 case and
    the encoder's actual error for the rest.
  - Round-trip for utf-8 -> gbk -> utf-8 is now provably
    lossless for "你好" / "Round trip: 你好" samples.

- `internal/api/encoding_test.go` (NEW): 8 unit tests.
  - `TestEncoding_Detect_GBK_HelloJsp` — GBK bytes for
    `你好` round-trip through `/api/v1/encoding/detect` and
    the integration smoke's expectation (`gbk` or
    `gb18030`).
  - `TestEncoding_Detect_UTF8BOM` — utf-8 file with BOM is
    reported as `utf-8-bom` with `hasBom: true`.
  - `TestEncoding_Detect_Plain_UTF8` — pure ASCII is
    `utf-8`.
  - `TestEncoding_Detect_ISO88591` — `0xC0 0xE0 0xF1` (not
    valid UTF-8) is **not** mis-detected as utf-8.
  - `TestEncoding_Recode_GBK_to_UTF8` — recode a GBK JSP
    to UTF-8, then re-detect, confirm content + new encoding.
  - `TestEncoding_Recode_UTF8_to_GBK_Roundtrip` — full
    round-trip preserves the Chinese text.
  - `TestEncoding_Recode_AddsBOMForUtf8BOM` — saving as
    `utf-8-bom` produces a real `EF BB BF` prefix.
  - `TestEncoding_Detect_MissingFileReturnsErrorEnvelope` —
    missing file returns a clean `io_error` envelope, not a
    panic.

### Frontend (TypeScript)

- `packages/encoding-extension/src/browser/encoding-service.ts`:
  Rewrote the service around Theia's `EncodingRegistry` +
  `FileService.read/write` + browser `TextEncoder` /
  `TextDecoder`. New methods:
  - `setEncodingFor(uri, encoding)` — register a per-URI
    override, update the local cache, return whether the
    encoding actually changed.
  - `getEncodingFor(uri)` — synchronous lookup that
    honours the override.
  - `readWithEncoding(uri, encoding)` — explicit read for
    the "Reopen with Encoding" flow.
  - `writeWithEncoding(uri, text, encoding)` — explicit
    write for "Save with Encoding".
  - `canEncode(text, encoding)` — round-trip check used
    to refuse a save when the buffer contains a char the
    chosen encoding cannot represent.

- `packages/encoding-extension/src/browser/encoding-commands.ts`:
  Rewrote the three commands. They now do real work:
  - `kairo.encoding.show` — surfaces the current encoding
    via `MessageService`.
  - `kairo.encoding.reopen` — picks an encoding via
    `QuickInputService`, registers the override, then
    closes the open editor and re-opens the file via
    `EditorManager`. The new file content is read with
    the new encoding.
  - `kairo.encoding.save` — picks an encoding, runs
    `canEncode`, writes the model with the chosen
    encoding via `FileService.write({ encoding })`, marks
    the document as not dirty, and registers the
    override so future Ctrl+S uses the same encoding.
  - All three are registered as `CommandContribution`
    (this was a pre-existing bug in `KairoViewsContribution`
    too — the `registerCommands` method existed but no one
    called it, so BUILD / START_SERVER / etc. never showed
    up in the palette).

- `packages/theia-product/src/main/browser/kairo-status-bar-contribution.ts`:
  The `kairo.encoding` status bar entry is now real:
  - Tracks `editorManager.onCurrentEditorChanged` and
    refreshes whenever the active editor changes.
  - Shows `Encoding: utf-8` for default, `Encoding: gbk *`
    when an override is in effect (the `*` is the
    "non-default" marker).
  - Tooltip includes the URI, the encoding label, and
    whether it is a default or an override.

### Bug fixes that came along for the ride

- `KairoViewsContribution` and the new
  `KairoEncodingCommandsContribution` are now bound as
  `CommandContribution` in
  `kairo-product-frontend-module.ts`. The pre-existing
  `registerCommands(registry)` method on the views was
  never called before; now the BUILD / START_SERVER /
  STOP_SERVER / DEBUG_SERVER / RESTART_SERVER /
  BUILD_AND_DEPLOY / SCAN_PROJECT / OPEN_APPLICATION /
  REVEAL_KAIRO_SERVERS commands should actually appear in
  the command palette. (We did not test these in this
  round; that is P4's job.)

- `internal/encoding/encoding.go` `Detect` was silently
  mis-detecting invalid-UTF-8 bytes as utf-8 when the
  project default was utf-8. The fix lives behind the
  new `canDecodeAs` helper.

## What is NOT in this tag

- **Search-and-replace preserves per-file encoding.** The
  search engine already reads bytes (not strings), and
  the per-URI override is honoured on every FileService
  read/write. So a GBK file's find-and-replace round-trips
  correctly *as long as the user opened the file with
  Kairo: Reopen with Encoding (or the editor was opened
  with the override already in effect). For files that
  were never auto-detected, find-and-replace is still
  the search-extension's existing string-based path;
  extending the search UI to surface the active file's
  encoding in its results panel is a small follow-up.
- **"Plain save" (Ctrl+S) cannot be hard-blocked when the
  override exists but the buffer has unencodable chars.**
  The canEncode guard is wired into the explicit "Save
  with Encoding" command; the `core.save` override is a
  follow-up. For now, the worst-case behaviour is the
  Theia default: invalid chars are written as U+FFFD
  in the chosen encoding. We log a warning in the
  progress doc because this is the user-visible
  failure mode that motivated the user's spec.
- **Auto-detect on first open.** Today, the user must
  invoke "Kairo: Reopen with Encoding" once per
  non-UTF-8 file. A follow-up will hook
  `EditorManager.onCurrentEditorChanged`, run the
  agent's detect, register the override, and reopen
  automatically.
- **Tarball extraction for the JDT LS.** Still
  downloading a single .jar — when Eclipse's URL
  scheme moves to .tar.gz, the agent needs an
  unpacker. Tracked as `v0.3-jdt-ls-bridge` work.
