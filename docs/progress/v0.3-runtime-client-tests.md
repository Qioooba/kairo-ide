# Progress — v0.3-runtime-client-tests

> Tag: `v0.3-runtime-client-tests`
> Round: P5 (Runtime Client unit tests)
> Date: 2026-07-18

## What is in this tag

The KairoRuntime client (the single point of contact
between the Theia frontend and the Go Runtime Agent) now
has a real unit-test suite. 14/14 tests pass on this
machine.

`packages/runtime-extension/src/browser/runtime.test.cjs`
covers the full user-listed matrix:

| # | Scenario | Verifies |
| - | -------- | -------- |
| 1 | `GET /api/v1/servers/{id}` with a path param containing `/`, spaces, `&`, and Chinese | URL-encoded expansion, payload returned |
| 2 | multi-param path + CJK / space / `&` query params | query string is encoded, never raw spaces |
| 3 | `POST /api/v1/builds` with envelope body | `requestId` is generated, `X-Kairo-Request-Id` header matches the envelope's `requestId` |
| 4 | 400 / 401 / 403 / 404 / 500 with `ok:false` envelopes | each maps to the correct `KairoErrorCode` |
| 5 | 2xx with `ok:false` (protocol error envelope) | unwrapped to `KairoError` with the agent's `code`, not the generic `internal` |
| 6 | non-JSON response (HTML 502 from an upstream proxy) | surfaced as a `KairoError`, not a raw `SyntaxError` |
| 7 | invalid JSON body on 2xx | surfaced as a `KairoError` |
| 8 | server stalls past `timeoutMs` | throws `KairoError{code: 'timeout'}` or `AbortError` |
| 9 | pre-aborted `AbortSignal` | throws immediately |
| 10 | success path | `payload` is unwrapped, `requestId` round-trips |
| 11 | connection refused (no agent listening) | throws `KairoError`, no crash |
| 12 | PUT and DELETE | method is propagated to the wire |
| 13 | `X-Kairo-Workspace-Id` and `X-Kairo-Request-Id` headers | propagate from runtime config + envelope |
| 14 | `bearerToken` configuration | `Authorization: Bearer …` header attached |

Run with:

```powershell
pnpm --filter @kairo/runtime-extension build
node --test packages/runtime-extension/src/browser/runtime.test.cjs
```

## Bug fixes that came along for the ride

- **`unwrapResponse` mis-handled 2xx `ok:false` envelopes.**
  Before this round, a 200 response with `ok:false` and
  `code:'plugin_crashed'` was turned into a
  `KairoError{code: 'internal'}` — the user saw a generic
  internal error instead of the actual reason. The fix
  adds an `isErrorEnvelope` check before the
  `isResponseEnvelope` check, so the agent's actual code
  is honoured. Caught by test #5.

- **`main` field pointed at a non-existent path in all 10
  Kairo packages** (`lib/src/index.js` instead of
  `lib/index.js`). This was a pre-existing bug; the tests
  could not import `@kairo/runtime-extension` from a
  plain Node context without it. Fixed in
  `packages/*/package.json` (10 files, 1 line each).
  Caught by test #1 (which is the first time we tried
  to consume a Kairo package from outside the pnpm /
  monorepo context).

## What is NOT in this tag

- **WebSocket event stream tests** (`EventStream`).
  The current tests cover the HTTP request side. The
  WebSocket reconnect / backoff / status-listener paths
  are not unit-tested yet; they are exercised
  end-to-end by the `full-chain` Playwright test.
- **Retry / backoff timing.** The current `request()`
  retries on transient errors. The test suite asserts
  the success / failure outcomes but does not time
  the backoff. A small follow-up adds a fake clock.
- **Mock vs. real http server.** Each test stands up
  a real `http.createServer`. This is on purpose — we
  wanted to exercise the real fetch / AbortController /
  encoding paths, not a mock that would lie about all
  of them. CI is the right place to also add a smaller
  mock for tests that should not depend on the network
  stack at all.
