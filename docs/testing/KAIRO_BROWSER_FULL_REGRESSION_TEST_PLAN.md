# Kairo IDE 浏览器端全量功能回归测试方案

**文档版本**: v1.0  
**创建日期**: 2026-07-25  
**测试框架**: Playwright + 内置浏览器截图模拟点击  
**执行方式**: 多工程师并行分片测试  
**预计总工时**: 8工程师 × 2天

---

## 一、测试概述

### 1.1 测试目标
对 Kairo IDE 浏览器版进行**全量功能覆盖测试**，确保所有模块在浏览器环境中正常工作，包括但不限于：
- IDE 核心 Shell 加载与布局
- 项目导入与文件管理
- Java/JSP/XML/SQL 等多语言编辑
- 智能补全、跳转、重构等语言服务
- 构建、部署、Tomcat 运行闭环
- 断点调试、热部署、热重载
- 搜索、Git/SVN 版本控制
- 编码检测、多编码支持
- JUnit 测试运行
- UI 主题、快捷键、无障碍访问

### 1.2 测试环境要求

| 环境项 | 要求 |
|--------|------|
| 操作系统 | macOS 12+ / Windows 10+ / Ubuntu 20.04+ |
| Node.js | ≥ 20.10.0 |
| pnpm | ≥ 9.0.0 |
| JDK | JDK 1.6.0_45 (用于Tomcat运行验证) |
| 浏览器 | Chromium (Playwright内置) |
| 内存 | ≥ 8GB |
| 端口 | 3000 (Theia), 8080 (Tomcat), 8899 (Runtime Agent) |

### 1.3 启动顺序
```bash
# 终端1: 启动后端Runtime Agent
cd /path/to/kairo-ide
pnpm agent:run

# 终端2: 启动浏览器版IDE
pnpm dev:browser

# 终端3: 执行测试
cd tests/e2e
npx playwright test --workers=1
```

### 2.1 分层测试策略


### 2.2 并行测试分片策略

将测试分为 **8个独立分片**，每个工程师负责1个分片，可完全并行执行，无依赖冲突。

| 分片ID | 负责工程师 | 测试模块 | 预计用例数 | 预计耗时 |
|--------|-----------|----------|-----------|---------|
| SHARD-01 | 工程师A | IDE启动 + Shell布局 + 状态栏 | ~35 | 3h |
| SHARD-02 | 工程师B | 项目导入 + 文件资源管理器 + 多标签编辑 | ~40 | 3.5h |
| SHARD-03 | 工程师C | Java语言服务 (补全/跳转/重构/诊断) | ~50 | 4h |
| SHARD-04 | 工程师D | JSP/XML/Properties多语言编辑 | ~35 | 3h |
| SHARD-05 | 工程师E | 构建 + 部署 + Tomcat服务器管理 | ~45 | 4h |

| SHARD-08 | 工程师H | SQL/JUnit/远程 + UI主题/无障碍/视觉回归 | ~40 | 3h |

### 2.4 截图验证规范

每个关键步骤必须截图，截图保存路径: `test-results/screenshots/{SHARD-ID}/{TEST-ID}/{STEP-NUM}-{description}.png`

截图时机：
- 页面/视图首次打开时
- 关键操作执行前后对比
- 出现错误/异常状态时
- 测试完成时最终状态
