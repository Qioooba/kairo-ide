## 缺陷台账

### BUG-20260826-200 (P1) — kairo.general.showWelcome=false 完全失效
**现象**: 设置 `kairo.general.showWelcome=false` 后重启，Welcome 仍然自动打开；反之关闭该偏好后 Welcome 又可能永远不再打开。

**根因（三处叠加）**:
1. `packages/theia-product/src/main/browser/kairo-views-contribution.tsx:764` — `maybeOpenWelcome()` 在 onStart 阶段读取偏好时 PreferenceService 尚未同步持久化用户设置，`get('kairo.general.showWelcome', true)` 永远返回 schema 默认值 true。修法：先 `await this.preferences.ready`（5s 上限兜底）再读取。
2. 同文件 `onStart()` — 在 onStart 里 addWidget(Welcome) 会与随后的 ShellLayoutRestorer 竞争：restorer 用上次会话保存的布局整体替换 main area，若其中没有 Welcome 则刚加的 tab 被丢弃（这正是"有时能开有时不能"的根源）。修法：把 `maybeOpenWelcome()` 从 `onStart()` 移到新增的 `onDidInitializeLayout()`（布局初始化完成后触发）。
3. `packages/theia-product/src/main/browser/kairo-welcome-widget.tsx` — 即便上述两处修好，布局恢复器仍会把上一会话遗留的 Welcome tab 复活（违背"不再自动打开"）。修法：widget 内置守卫 `installShowWelcomeGuard()`——订阅 `preferences.onPreferenceChanged` 并在 ready 后求值，当 `showWelcome===false` 且本会话非显式请求（Help > Welcome 通过新导出的 `markWelcomeExplicitlyRequested()` 标记）时自关闭。

**修复验证**: 单测序列 probe + 全套 ch08 回归 9/9 通过（抑制、恢复双向均验证）。
