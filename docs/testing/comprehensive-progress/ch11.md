## 本章修复的缺陷

### BUG-20260826-300 — Git 集成从未接入浏览器构建（P1）
- **关联用例**: TC-NAV-005（及第29章 Git 全部）
- **位置**: `packages/git-extension/**` 未被任何前端模块绑定；`packages/git-extension/src/browser/git-service.ts:6` 直接 `import { execFile } from 'node:child_process'`
- **根因**: ①`@kairo/git-extension` 既不是 app/theia-product 的依赖，也没有 `theiaExtensions` 声明——装饰器、SCM 视图、状态栏分支等整个包在浏览器 bundle 中缺席；②即使接入，浏览器 bundle 中 child_process 是抛错桩（esbuild-plugins-node-modules-polyfill），所有 git 命令必败。
- **修法**: 按 svn-extension 既有模式补齐：
  - 新增 `src/common/git-protocol.ts`（GitBackendPath=/services/kairo-git-backend，$exec/$findRepoRoot/$findNearestRepoRoot）
  - 新增 `src/node/git-backend-service.ts` + `git-backend-module.ts`（真实 git CLI，C locale）
  - 前端 `GitService` 改为 JSON-RPC 代理后端（保留解析逻辑），并注入 `WorkspaceService` 启动时自动探测 repo root；无 repo 时每 ~12s 重探（支持 IDE 开着时 git init）；向下扫描一级子目录找 `<workspace>/<project>/.git`
  - `kairo-product-frontend-module.ts` 调用 `bindGitExtension(bind)`；git-extension/package.json 增加 `theiaExtensions.backend`；theia-product 依赖增加 @kairo/git-extension 并加入 tsconfig references
  - 附带修复 `GitExplorerDecorator` 在构造函数中访问注入属性（inversify 属性注入发生于构造之后，ES2022 类字段为 undefined）→ 移入 `@postConstruct`
- **回归**: TC-NAV-005 通过；M/A/? 三种状态颜色+tooltip 正确。

### BUG-20260826-301 — 工作区子目录项目的 .kairo/project.yaml 不被识别（P1）
- **关联用例**: TC-NAV-006（编码 override）、第9/10章导入相关
- **位置**: `packages/runtime-extension/src/browser/workspace-context-service.ts` refreshProjectYaml；`packages/project-extension/src/browser/active-project-service.ts` projectInfoFromYaml
- **根因**: 仅在工作区根读 `.kairo/project.yaml`。通道工作区布局为 workspace/legacy-sample/.kairo/project.yaml → 检测不到 → ActiveProject 为 "(not imported)" → 项目编码 gbk 不注册 → GBK 文件按 UTF-8 解码成乱码（CHANGED����ӭʹ��）。KAIRO-RC-WEB-029"打开文件夹即自动加载"承诺失效。
- **修法**: refreshProjectYaml 向下一级扫描非隐藏子目录的 .kairo/project.{yaml,yml}；新增公开 getter `detectedProjectRoot`（拥有该 yaml 的目录 OS 路径）；projectInfoFromYaml 以 detectedProjectRoot 为基准解析 root。
- **回归**: TC-NAV-006 中文正常显示；状态栏项目名正确。

### BUG-20260826-302 — 浏览器键盘守卫导致所有受保护快捷键失效（P0）
- **关联用例**: TC-NAV-004（⌘⇧O）、TC-ED-001~010 大量快捷键、CMD 系列
- **位置**: `packages/theia-product/src/main/browser/kairo-browser-keyboard-guard.ts:164`
- **根因**: Theia `KeybindingRegistry.run()` 首行 `if (event.defaultPrevented) return;`。守卫在 window capture 阶段 preventDefault() 后，注册表直接放弃分发 → ⌘S/⌘W/⌘⇧O/⌘D/⌘F… 约 100 个 IDEA 快捷键在浏览器全灭（仅 Monaco 内部命令幸存）。
- **修法**: 守卫改为 preventDefault + stopPropagation 后，构造干净合成 KeyboardEvent（保留 key/code/修饰键）标记 `__kairoGuardClone` 再向原 target 派发，让注册表/Monaco 正常接收；克隆事件跳过守卫防递归。另对 INPUT/TEXTAREA/contenteditable 目标跳过守卫（保留原生编辑行为），仅 Chrome 保留导航键（cmd+n/t/w/tab/f5/cmd+r/cmd+p 等）仍拦截。
- **回归**: ⌘⇧O 直接打开 Find File 浮层 ✓；后续 ED 各用例键盘操作均依赖此修复。

### BUG-20260826-303 — Escape 无法关闭对话框 / Shift+Escape 绑定到不存在的命令（P1）
- **关联用例**: TC-NAV-003（确认框交互）、TC-CMD-005
- **位置**: `kairo-focus-management.ts:120`（escape→kairo.focus.editor 无 when 保护）、`kairo-idea-mac-keymap.ts:146` 与 `kairo-idea-windows-keymap.ts:145`（workbench.action.hideActivePanel 在 Theia 1.73 中不存在）
- **根因**: KeybindingRegistry 挂在 document capture 阶段，执行命令后吞掉事件 → 对话框 body 监听永远收不到 Escape；hideActivePanel 则是空命令，Shift+Escape 无任何效果。
- **修法**: 移除 escape 键注册表绑定（保留 kairo-focus-management 的 document bubble 级全局 keydown，其已有输入框/对话框目标过滤）；新增 `kairo.hideActivePanel` 命令（隐藏底部面板，否则折叠焦点所在侧栏），两个平台键位图将 Shift+Escape 指向它。
- **回归**: NAV-002/003 对话框 Esc/按钮关闭正常。
