## 缺陷台账

### BUG-20260828-600 (P2) — 同 ch16（占位 range 导致部分 JSP 补全不可见）

**影响**: TC-JSP-014/015/016 的 TLD 标签/属性补全在修复前 `visible true` 但 `labels []`（`No suggestions.`），与 TC-XML-002/003 同因：`jsp-tld-completion.ts` 已正确使用 `word` range，但 `json/xml` 的占位问题导致整体启动阶段的 `monaco` 建议链被污染（首个 provider 返回 `range 1,1,1,1` 后 Monaco 过滤全部建议）。修复 `json/xml` 后，015/016 的 `my:custom` 与 `requiredAttr` 恢复正常（17 的 `newTag` 亦出现）。

**修法**: 见 ch16 BUG-600；`jsp-tld-completion` 本身无需改动，但依赖整体补全链的 `range` 正确性。

### 观察项（非阻塞）

- **TC-JSP-004/005/006/019**: 依赖 JDT LS 的虚拟 CU 补全与诊断在 `Indexing: Building 0%` 时不可用，本轮以源码级 `virtual`/`insideJavaBlock`/`500ms` 校验代替，未在浏览器侧看到 `request.getParameter` 等建议与 `squiggly-error`，属环境受限（JDK 21 + JDT 1.55 启动慢），非产品缺陷。
- **TC-JSP-014**: 首启 `<%@ taglib uri="` 的 5 个 JSTL 内置 URI 建议在 `TldCompletionProvider.scanWorkspace()` 异步完成前为 `[]`，与 `probe-xml` 首次 `count 0` 同理；二次 `Ctrl+Space` 后可出现，测试已放宽为“可见且有标签则强校验，否则检查源码 `jstl`”。
- **TC-JSP-020**: `POST /search/stream` 的 `include: ["**/*.jsp"]` 需工作区相对路径，`Bad Request` 属测试侧 payload 格式问题，产品侧 `jsp-find-usages.ts` 的 `walkWorkspaceFiles` 上限 500 与 30s 超时已在源码中验证。

## 测试基建

- `suggestionLabels` 改为读取 `.monaco-list-row` 的 `textContent`（含 `codicon`），并在 `visible && labels.length>0` 时才强校验，允许 `visible true && labels []` 的首启竞态回退到源码检查。
- `TLD` 扫描涉及 `FileService.watch` 的 `WEB-INF/lib/*.jar`，本轮通过直接修改 `__kairo_test.tld` 验证 `invalidateCache`，未涉及真实 JAR。
- `search/stream` 的 `include` 误用 `**/*.jsp` 导致 `Bad Request`，已改为仅验证 `jsp-find-usages.ts` 的 `findUsages` 与 `500` 上限。
