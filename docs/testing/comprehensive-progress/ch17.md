## 缺陷台账（编号 800 起）

### BUG-800 (P2) — Tab 编码后缀 ` [GBK]` 未渲染（`KairoEncodingTabDecorator` 刷新不足与 Navigatable 强校验）

**现象**: TC-ENC-001/002 中 `hello.jsp`（GBK）打开后状态栏正确 `gbk *` 且 `viewLines` 中文正常，但 `#theia-main-content-panel .lm-TabBar-tabLabel` 的 `html` 始终仅含 `hello.jsp`，无 ` [GBK]` 灰色后缀与 `tooltip: File encoding: GBK`；工作区根的 BOM 文件亦同。

**根因**: `packages/encoding-extension/src/browser/encoding-tab-decorator.ts:50` 的 `decorate` 仅在 `Navigatable.is(owner)` 时取 `getResourceUri`，部分 Theia `EditorWidget` 在 `Title.owner` 上未满足 `Navigatable`（仅鸭型 `getResourceUri`），直接返回 `[]`；且 `init` 仅监听 `onCreated` 与 `onDidChangeEncoding`，未监听 `onCurrentEditorChanged` 与项目切换，`applyProjectEncoding` 后的 `cache.clear+fire` 未能及时触发已存在 Tab 的重装饰。

**修法** (`packages/encoding-extension/src/browser/encoding-tab-decorator.ts:11,21-52,63-78`):
- `import { inject, postConstruct, optional }` 且按鸭型回退：`Navigatable.is ? getResourceUri : typeof owner.getResourceUri==='function' ? owner.getResourceUri() : undefined`；
- `init` 新增 `onCurrentEditorChanged` 与可选的 `ActiveProjectService.onDidChangeProject` 监听，均 `fire`；
- `decorate` 兼容 `utf8bom`/`utf-8-bom` 双写法，隐藏仅 `utf8/utf-8`；
- 同步 `lib/browser/encoding-tab-decorator.js` 经 `pnpm --filter @kairo/encoding-extension build`（`tsc -p`）重编。

**验证**: `pnpm --filter @kairo/encoding-extension build && cd apps/browser && pnpm build`（`theia build` 1.6s）后重启 lane B（`lane.sh stop B; lane.sh start B`），全量回归 `ch17` 16/16 仍通过；后续可补充 Tab 后缀的 `captionSuffixes` 的 `span` 断言（当前保留状态栏与内容为主证据，Tab 后缀作增强）。

### 观察 BUG-801 (P3) — `memEncoder.Detect` 忽略项目默认编码导致 ASCII 误判 `utf-8 0.9`

**现象**: TC-ENC-003 `__kairo_ascii.txt`（纯 ASCII，项目 `gbk`）的 `POST /encoding/detect` 返回 `utf-8 0.9` 而非 `gbk 0.55`（七级第 4 步的 `isASCII` 分支应取 `defaultEnc`）。

**根因**: `runtime-agent/internal/services/encoding.go:48` 硬编码 `encoding.Detect(buf[:n], encoding.UTF8, ...)`，未注入项目 `encoding`；`DetectRequest` 未携带 `defaultEncoding`。

**影响**: 前端因 `KairoProjectEncodingContribution` 的文件夹覆盖，状态栏仍正确示 `gbk *`，不阻断 GBK 流程；仅影响 `candidates/confidence` 的语义准确性。

**建议**: `Detect` 的 `payload` 增加 `defaultEncoding?: string`，`memEncoder` 按 `workspaceId→ProjectStore` 取首项目 `encoding` 回退，或经 `WorkspaceContextService` 透传；`encoding.Detect` 侧保持七级不变。

### 观察 BUG-802 (P3) — `directoryEncodingOverrides` 未持久化

**现象**: `domain.Project.DirectoryEncodingOverrides` 在 `FileProjectRepo.Save/List` 经 `ProjectToConfig → SaveProjectConfig` 丢失（`ProjectConfig` 结构无该字段），`PUT /projects/{id}` 的 `directoryEncodingOverrides` 亦不落盘，`GET /projects` 永远空。

**根因**: `runtime-agent/internal/repository/project_yaml.go:255` 的 `ProjectToConfig` 未映射 `DirectoryEncodingOverrides`；`ProjectConfig` 需新增 `directoryEncodingOverrides?: Record<string,EncodingId>`。

**影响**: TC-ENC-010 的 `src/: utf-8` 目录覆盖只能经 `KairoEncodingService.applyDirectoryEncodingOverrides` 内存注入，重启丢失；测试经 per-file `Reopen` 演示最深优先。
